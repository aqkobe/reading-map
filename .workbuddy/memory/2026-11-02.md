# 2026-11-06 追加3（云端数据被清空事故）
- 根因：joinFamily 中 save() 先于 doPull()，新设备(空数据)的 800ms 防抖推送跑在拉取前；且 doPush 读云端失败被 catch 吞掉当"云端没数据"→ 空数据覆盖云端。startSync 无论成败都显示"已同步"掩盖问题。
- 四层修复：①doPush 读云端失败不推送 ②空覆盖保护(本机空+云端有→只拉不推) ③自愈(doPull 发现云端空+本机有数据→自动 schedulePush 恢复) ④doPull 返回成败、startSync/joinFamily 如实提示；joinFamily 改为先拉后存。
- 数据恢复：有数据的手机刷新新版后 15 秒内自动补回云端。

# 2026-11-06 追加5（Chrome 同步失败实锤）
- 实锤：WorkBuddy 本地预览服务器(127.0.0.1)给页面注入 CSP 响应头，connect-src 白名单不含 *.supabase.co → 预览窗口里打开页面时所有 Supabase 请求被浏览器拦截 → 必然"同步失败"。REST 直测正常，DR4HGM 数据完整（我想长大/不爱说话的小光等书目都在）。
- 结论：云和代码都没问题，是打开方式的问题。桌面端同步请用 file:// 直接打开 HTML 或正式部署链接，不要用受限预览窗口。
- 加固：doPull/doPush catch 中 warnBlockedOnce()——检测到 localhost/127.0.0.1 环境时 toast 提示"预览环境拦截了联网，请直接打开 HTML 文件或用正式链接"。

# 2026-11-12 工作日志

## 手机后台挂久了看不到家人最新记录（同步修复，0.09）
- 现象：晚上 A 手机打卡显示已同步，B 手机看不到；白天浏览器新开页面就能同步成功。
- 根因（叠加）：
  1. B 手机页面在后台挂几天后，15s 轮询 + realtime 都已失效，但「已同步 ☁️」标签是静态的、停留在上次成功状态 → 误导。
  2. 手机页面不重新加载就一直跑打开当天的旧代码（可能早于同步修复版本），永远不会自愈。
- 修复（commit 3fe8ddf，已推送并验证线上 BUILD='20261112a'）：
  1. `BUILD` 版本戳 + `checkNewVersion()`：回前台/online/pointerdown 时 `fetch(location.href,{cache:'no-store'})` 核对版本（≥30 分钟间隔），不同则自动 reload（输入框聚焦时只提示不刷新）。
  2. 同步点改为「已同步 · HH:MM」，每次拉/推成功都刷新时间；`lastSyncOk` 记录最后成功时刻。
  3. `resumeSync()`（拉云端+核版本）挂到 visibilitychange / online / pointerdown(>30s) 三个事件上。
- 教训：`git push -c` 选项必须放在 push 前面（`git -c ... push`），否则报 unknown switch。
- 提醒：老手机需手动刷新一次页面，之后靠版本自检自动更新。

## 云组件 CDN 依赖是最后一个失效源（0.10，commit d86579d，BUILD 20261112b）
- 现象：手机刷新后云同步区不显示（SB=null 显示「仅本机」），换浏览器输共享码失败（"激活失败"是旧版文案，现版代码里根本没有这个字符串 → 说明手机跑的还是旧页面）。
- 根因：supabase-js 从 cdn.jsdelivr.net 动态加载，国内手机网络经常失败 → SB=null → startSync 直接 return、joinFamily 拉不到云端。桌面浏览器正常是因为网络环境不同。
- 修复：① supabase-js v2 UMD（220KB）内嵌进 HTML（用 node 脚本插到 CONFIG 注释前，注意 HTML 注释原文是"填了才加载"）；② 双 CDN 兜底轮换（jsdelivr→unpkg，8s 超时）；③ 首页加「🔄 重新加载云组件」retryCloud 按钮；④ joinFamily 加 !SB 保护。
- 验证：Node vm 冒烟测试 createClient OK；线上 BUILD=20261112b 且含 supabase-umd-inline 标记。
- 架构要点：本应用是单文件离线应用，所有第三方依赖都应内嵌，不允许 CDN 动态加载。
- 部署陷阱再犯：`git add` 后忘 `git commit` 直接 push 报 "Everything up-to-date"（第二次了）——push 前必须确认有新 commit。

## 2026-11-13 补充：推送失败无补传机制（0.12，commit f464997，BUILD 20261113a）
- 现象：昨晚 B 打卡推送失败后数据憋本机一夜，A 显示"已同步·22:11"（真实——云端当时没 B 的数据），16:00 A 重开才收到。
- 根因：doPush 3 次重试失败后放弃，之后 15s 轮询只拉不推、resumeSync 也只拉不推——无补传机制。
- 修复：pendingPush 标记（schedulePush 置位、doPush 成功清位、localEmpty 清位）+ 四个补传时机（15s 轮询/回前台/online/启动拉取后）；SB 未就绪的改动也标记；失败 toast 节流 2 分钟。
- 认知：A 夜里收不到更新是页面冻结的系统行为，不可修；能修的是"数据在源头就卡住不上云"。

## 2026-11-14 根因实锤：*.supabase.co 在国内被 SNI 级间歇拦截（未迁移，用户选择维持现状）
- 实测证据：TCP 443 可连、DNS 正常（Cloudflare IP）、TLS 握手 5/5 次在 ~0.24s 内被重置（curl exit 35）；对照 supabase.com / cloudflare.com 直连均 200。典型 SNI 域名拦截，时好时坏。
- 这解释了全部历史现象：同步时好时坏、手机弱网失败多、白天浏览器能成功、DB 时间线断续。App 代码逻辑没有问题。
- 数据安全：各手机 IndexedDB 全量保留 + 0.12 自动补传，数据只晚到不丢失。
- 用户决定（2026-11-14）：先维持现状，不迁移。将来若升级：方案 A 迁腾讯云开发等国内后端（治本）；方案 B 买域名套 Cloudflare 反代（改善但不保证）。
- 注意本机测试也受此影响：curl Supabase REST 要走代理且代理也常失败（CONNECT 502 / SSL reset），直查云端数据要在 Supabase Dashboard 或网络通畅时段。
